# Coding Standards

How code in this repo is written. Reviewers (human and agent) check changes against this file. What TypeScript already enforces is not repeated here.

## View Contract

- Every tool result that renders a View is built with `encodeViewResult`, and every view reads it back with `recoverView`. The View shapes live only in `view-contract.ts`; server and UI import them from there.
- Extend a View by adding fields. Unknown keys are stripped on parse, so an older UI keeps working against a newer server; a renamed or removed field breaks it.
- The duplicate JSON text block stays until [ADR-0001](docs/adr/0001-view-carried-twice.md) is revisited.

## Tools

- A tool description is a prompt for the calling model: say when to call it and how to resolve its inputs (e.g. "resolve the collection id with search_collections first").
- A failure the model can fix (unknown collection, dates outside the extent, a collection that cannot be mapped) throws `MapConfigError` with a message that names the fix. `corrective()` turns it into an `isError` result. Reserve plain exceptions for bugs.
- Guards on catalog metadata live in `server/dashboard-render.ts` and fail fast: the CDN in front of titiler masks upstream errors as an HTML page with status 200, so a map that silently fails to tile gives the model nothing to correct on.

## Views

- Each tool result renders one step View; interactions advance the chat through `app.sendMessage`. See [ADR-0003](docs/adr/0003-interactions-advance-the-chat.md).
- Each bundle is its own resource: `collection-picker.html` for the Picker, `map.html` for the Map View and Compare View, which it dispatches on `kind`. A View that needs a dependency set or CSP the existing bundles lack gets its own bundle; otherwise it joins the bundle it shares them with.
- Each resource declares the CSP for exactly the origins its bundle loads (`server/server.ts`). A View that starts loading a new origin adds it there in the same change.
- The picker entry stubs the map stack through the vite alias in `vite.config.ts`; a view that renders a component with stubbed dependencies breaks at runtime. Add a stub only for a dependency the entry never renders.
- Each `dist/*.html` bundle stays under 4 MiB, enforced by the CI `check` job: Vercel caps function responses at 4.5 MB and a resource read carries the whole bundle. A PR that bumps a dependency records the bundle sizes before and after.

## Server

- The HTTP transport is stateless: a fresh server and transport per request, no session ids, no per-user state. Module-level caches hold only public catalog data with a TTL. See [ADR-0002](docs/adr/0002-stateless-http-path-token.md).
- Environment variables are read and validated in `server/config.ts`, except `PORT`, which belongs to the long-lived HTTP transport in `server/main.ts`.
- `MCP_PATH_TOKEN` stays out of code, tests, docs, commits and logs: anything that prints the endpoint prints `/mcp/<token>`.

## Dependencies

- npm, with `package-lock.json` regenerated by `npm install`, never edited by hand.
- `@teamimpact/veda-ui-blocks` is pinned exactly (prerelease). Fixes to it go upstream; a local fix is a `patches/` file whose header says why it exists and when to delete it.

## Vocabulary

- Name things with the terms in [GLOSSARY.md](GLOSSARY.md) in code, tests, commits and docs, and respect its _Avoid_ lists. A concept that has no entry there gets one in the same change.

## Comments

- Comments explain why. Link only public URLs; no bare issue or PR numbers, which do not resolve where code is read.

## Tests

- Test at the highest seam that exercises the behaviour: the wire round-trip (`view-contract.test.ts`), map config against mocked STAC responses (`server/dashboard-render.test.ts`), the STAC client (`server/stac.test.ts`). Shared fixtures live in `server/test-helpers.ts`.
- Widget rendering and host delivery are verified in basic-host (see AGENTS.md), not in unit tests.

## Commits and PRs

- Conventional commits (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`). Short, factual.
- Issue-closing keywords (`Closes #N`) go in the PR body, never in commit messages.
- PRs target `main` and need the `check` CI run green.
